# Odin Group website — plan

Public catalogue of the apps and games Odin Group builds. Every app has its own page; every published version of
an app has a downloadable APK, its changelog and the phase it came from. Other projects push a new APK here after
each phase they finish.

Live at **https://www.odingroup.co.za** (GitHub Pages, custom domain).

## Decisions (owner, 2026-11-01)

| Topic | Decision |
| --- | --- |
| Hosting | GitHub Pages, public repo `mhmdfaour/odin-group-website`, served from the `gh-pages` branch |
| APK storage | GitHub Release assets on this repo (never committed to git) |
| Domain | `www.odingroup.co.za` (apex redirects to www once DNS is set) |
| Launch apps | Fawterly, ToolForge, Petriotic, Wormhole Rider (more added through the catalogue) |
| CI | None. Builds and deploys run locally (`npm run build`, `npm run deploy`). No custom GitHub workflows. |

## Architecture

```
catalog/
  apps/<slug>/
    app.json          # app metadata (schema in specs/phase-1-site.md)
    releases.json     # every published version, newest first
    icon.png          # 512x512
    screenshots/*.png
  site.json           # company name, tagline, contact, social links
src/                  # templates, styles, build script (Node, no framework)
tools/publish.mjs     # the one command other projects run after a phase (phase 2)
dist/                 # build output (gitignored), pushed to gh-pages by `npm run deploy`
```

- Static site generated by a small Node build script from `catalog/`. No runtime backend.
- APK download URL: `https://github.com/mhmdfaour/odin-group-website/releases/download/<tag>/<file>`,
  tag `<slug>-v<versionName>+<versionCode>`, file `<AppName>-<versionName>.apk`.
- Machine-readable feeds: `/apps/<slug>/releases.json` (per app) and `/updates.json` (site-wide, newest 50), so the
  apps can check for updates later.

## Pages

1. **Home** — Odin Group intro, grid of apps and games (filter: All / Apps / Games), "Latest updates" strip.
2. **App page** `/apps/<slug>/` — icon, name, tagline, description, screenshots, platform/min Android, big
   "Download latest APK" button (version, size, date), then **Version history**: one entry per version with phase
   label, date, changelog, size, SHA-256, download link. Each version has an anchor (`#v1.2.0`).
3. **Install help** `/install/` — how to install an APK on Android (allow unknown sources, verify SHA-256).
4. **About / contact** `/about/`.
5. 404 page.

## Phases

| Phase | Scope | Spec |
| --- | --- | --- |
| 1 | Site generator, design, catalogue for the 4 launch apps (metadata, icons, screenshots), deploy script, Pages + custom domain | `specs/phase-1-site.md` |
| 2 | `tools/publish.mjs` (validate APK, create Release, update catalogue, build, deploy), backfill the APKs that exist today, publishing guide for other projects | `specs/phase-2-publish.md` |

After phase 2 the main session adds the "publish your APK after each phase" rule to the global CLAUDE.md so every
project does it.
